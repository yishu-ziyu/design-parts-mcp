# pixel-touch

含原作素材，只留本机。

来源：Yashi Singh @yashisinghh，https://x.com/yashisinghh/status/2114279547416015008 ，2026-10-25。查看日期 2026-11-05。原帖是 4 段短视频。

## 机制

- 四幅像素图的格子颜色都从原帖视频截图取样（`source-assets/grids.js`）：先拟合格距，再取每格中心颜色；小屋和城区对 12 帧取众数，去掉移动中的光标、手机和弧线。
- 每格画成“格距减 1px”的方块，缝隙露出白底，所以看起来是拼豆。
- 地球：把截图反投影成经纬贴图，每帧按屏幕格子查球面颜色；拖动改经度，点击放标记，标记的连线和标签随地球转。
- 小屋：点小站后，一圈小方块按格错峰亮起，金额上飘，今日计数加一。
- 城区：手机吸附在格子上，能拖；弧线和最近两座塔的延迟数字跟着位置变。
- 圆环：按角度分成 13 块，各自带弹簧。点按时向外炸开，鼠标靠近时被推开。中间金币用横向缩放表示翻转。

## 可学

位移吸附到格子上，动起来依然是像素。把形状当作数据后，同一套逻辑可以画四种场景。

## 不学

不要把取样数据当成能任意转动的 3D 模型：地球背面是补出来的。文案 “SEALED / WITNESSED” 是原作产品的话，换成自己的内容。

## 和原版的差别

见结果文件的 gap。地球约一半表面没有截图依据，用同纬度对面的内容补；原版的建筑在光标附近有形变，这里没有。延迟数字按距离算，不是真实测量。
