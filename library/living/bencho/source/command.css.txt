/* THE MORPH PATTERN, and it is not the move one. Here the
   library owns x: it animates the element and its silhouette
   in perfect sync, so while the button is leaving the two are
   still one body of liquid, necking thinner until the goo
   gives up. That is the whole effect.

   It carries a second decision with it. Morph positions its
   items with a CSS transform on a real wrapper, in LAYOUT
   pixels, which scales correctly inside a scaled card on its
   own â so this component must NOT carry the 1/k correction
   every \`move\` group needs. Right for move, wrong for morph. */
const has = !!q.trim();

<Liquid blur={3} contrast={22} fill="var(--fill-slab)" shadow="...">
  <Liquid.Item>                        {/* the bar: never moves */}
  <Liquid.Item x={has ? 0 : -(BTN + GAP)}>   {/* the button */}

/* THE OFFSET IS ALL ON THE BUTTON. Splitting it between the
   two keeps the pair centred â which is what the reference
   does â but everything inside the bar travels with it, so the
   mic fading out was also sliding sideways. A thing leaving in
   two ways at once reads as neither. The bar holds still and
   the button walks out from under its right edge. */

/* THE FILL MUST BE OPAQUE. The goo is a blur then a steep
