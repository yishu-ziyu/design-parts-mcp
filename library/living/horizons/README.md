# horizons — 能调焦、能换机位的实时黑洞：拱和细环是光线弯出来的

来源：Bee（[@thtbee_](https://x.com/thtbee_/status/2113301369826464147)）的「Two Horizons」，three.js 官号[转发](https://x.com/threejs/status/2113400110415860193)。原作只发了录屏和两张参考图，没有公开代码。复刻程度：光线弯曲实算；界面布局照原作；农舍、宇航员、花田是示意。

调性一句话：一台对着黑洞的仪器——画面逐像素算出来，四角只放实时读数，中间全留给光。

## 这一页是什么

- 16:9 黑框里一块 WebGL 画布，每个像素从相机反向发一条光线、按引力弯曲一步步走：吸积盘在俯看机位被弯成一道宽拱，在贴盘机位变成一条亮线加洞上下一圈细环。
- 底部 ‹ › 在两个机位之间移动相机。两个场景是同一个 shader 的一个参数，过渡是连续的，不是切图。
- 右侧竖刻度是焦距，18–85mm，滚轮或拖动。
- 地平线上叠一层 2D 剪影给尺度：俯看是亮窗农舍 + 皮卡，贴盘是宇航员背影 + 散景。
- 四角：左上标签 + 场景名 + 一行说明；右上暂停 / 全屏；左下 ALT / HORIZON（Rs）、帧率与渲染比例、运行时钟。
- 页尾「可拆」6 条：`#lensing` `#viewpoint` `#focal` `#scale` `#hud` `#fps`。

## 作者与方法

事实：

- 作者说：给模型两张参考图，要求尽可能还原，全程用 three.js，用时 1 小时 40 分钟。原帖写的模型是 Gemini 4 Carbon。两个场景的构图和颜色都在追这两张参考图。
- 没有公开代码。评论里有人说着色器效果像 @XorDev 的写法。
- 这类画面的公认参照是电影《星际穿越》的黑洞：特效团队和 Kip Thorne 2015 年把做法写成论文——从相机反向追踪光线，按广义相对论计算弯曲路径（[arXiv:1502.03808](https://arxiv.org/abs/1502.03808)）。

推断：

- Aurum 参考图农舍下方有 CHILLIGRID 水印，可能出自别人的作品或某个生成平台，来源没有核实。
- 盘上很细的气体丝应该是多层噪声按开普勒速度旋转后叠出来的；具体参数没公开。

## 参数

两个机位是同一组 uniform 在 `sc = 0 → 1` 之间插值：

| 参数 | 俯看（sc=0） | 贴盘（sc=1） |
|------|------|------|
| 相机距离 | 19 | 34 |
| 仰角 | 0.17 rad | 0.022 rad |
| 俯仰修正 | 0.035 | −0.01 |
| 地平线（屏幕 y） | −0.30 | 0.012 |
| 盘外径 / 内径 | 13 / 2.6 | 10 / 2.6 |
| 盘亮度倍数 | 1.05 | 2.8 |
| 星空强度 | 0.8 | 0.04 |
| HUD：ALT / HORIZON | 3.21 / 18.0 Rs | 0.75 / 33.0 Rs |

| 光线与相机 | 值 |
|------|------|
| 弯曲 | 每步 `vel += −1.5·h²·pos/r⁵·dt`，h = pos × vel，视界 Rs = 1 |
| 步数 / 步长 | 最多 130；`clamp(0.06r, 0.025, 1.5)` |
| 结束条件 | r < 1 吸收；r > 60 且远离才逃逸（去星空取色）；步数用完按吸收 |
| 盘旋转 | 开普勒角速度 `2.2 / r^1.5` |
| 盘密度 | `smoothstep(0, .08, x)·(1−x)^1.6·(.35 + 2.6·fil·fil2)`，fil、fil2 是两层 5 阶 fbm |
| 朝镜头增亮 | `clamp(1 + .45·cos, .25, 2)^2.2` |
| 收尾 | 暗角 `1 − .28·uv²`，色调映射 `1 − exp(−1.15c)`，gamma 0.95 |
| 焦距 | 18–85mm，默认 50，`fov = 2·atan(12/mm)`，滚轮 0.025mm/单位 |
| 换机位 | `cur += (target − cur)·min(1, dt·1.4)`，时间常数约 0.7s；场景名淡出 0.4s，350ms 换字 |
| 渲染比例 | 初值 0.7，每 0.6s：帧率 < 40 降 0.1，> 58 升 0.05，范围 0.4–0.9 |

## 实现要点

- **规则先于形状**：第一版用 2D 着色器画一个圆环加一条光带，正面像，相机一动就假。改成逐像素追踪光线后，拱和细环由弯曲算出来；相机从俯看移到贴盘，拱和细环的位置变化和原作一致。
- **没跑完的光线算被吸收**：贴盘视角下，步数用完还没逃出去的光线曾被当成逃逸，视界里出现亮点。现在只有确实飞远（r > 60 且在远离）的光线才去取星空。放大视界中心验证，没有杂点。
- **星空哈希不用 sin**：用 sin 做的随机数在星空里出现斜条纹，换成不含三角函数的哈希后消失。盘和地面的值噪声仍用 sin 哈希，那里看不出条纹。
- **盘是前后叠的**：光线每次穿过 y = 0 平面，在交点取一次盘色，按 `col += (1−al)·c·a` 从前往后累积不透明度；拱是盘的背面被弯过来的那一次穿越。
- **两层画布**：光追画布按渲染比例 Q 降分辨率；2D 剪影层按 devicePixelRatio 满分辨率画，剪影边缘不会跟着糊。
- **暂停只停时间**：暂停冻住盘的旋转和花田闪光（shader 的 t）；换机位、焦距、读数照常响应。
- 读数和 shader 用同一组插值：ALT = 距离·sin(仰角)，HORIZON = 距离 − 1。

可学之处（原笔记的要点）：

1. 复杂形状先找规则。光线怎么弯写对了，拱和细环会自己出现，换角度也不会穿帮。
2. 两个场景是同一个模型换机位：相机抬高是一个，压到盘面高度是另一个。
3. 放一个小的人造物给出尺度。农舍、皮卡、宇航员都很小，黑洞才显得大。
4. 界面上只放真实参数。相机高度、离视界的距离、帧率都是实时数值，看起来像在操作一台仪器。

## 和原作的差距

| | |
|------|------|
| 盘的细节 | 原作有很细的气体丝和尘埃颗粒；这里只有两层噪声，近看偏糊 |
| 贴盘机位 | 原作的环更厚、过曝更强，地平线那条光带更亮；这里偏暗 |
| 宇航员 | 原作是写实的宇航服；这里是平面剪影加渐变 |
| 性能 | 每像素最多 130 步，普通笔记本上会自动降到 40%–60% 分辨率来保帧率 |

- **file:// 直开，运行时零网络**：`grep http index.html` 为空。
