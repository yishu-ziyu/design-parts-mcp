# flycam — 可见相机穿行 2D 画布（红鲱鱼与枪证据飞行版）

来源：https://x.com/KMkota0/status/2097648429727904197 （5s 屏录，60fps；逐帧拷贝在 `_source/km-tweet.mp4`）。

调性一句话：左窗格里那台黄色线框相机是主角，右窗格只是它的眼睛——相机沿虚线走，证据墙迎面掠来。

## 逐帧机制（基于 ffmpeg 抽帧对照，非凭印象）

- **布局**：一个窗口分左右两窗格 + 底部时间轴。左 = 暗灰 3D 编辑视图（场景从外侧看，照片墙是灰阶的）；右 = 全彩渲染结果。底部橙色进度条 + 白色菱形刻度 + 蓝色播放头，播放头与两窗格严格同步。
- **左侧 rig**：黄色线框视锥（金字塔、正面有交叉对角线、顶边一枚朝向小三角、apex 处黄色六边形机身），黄色六边形路径点 + 黄色虚线连成航线。播放时视锥沿虚线平滑移动（段内缓动，非匀速瞬跳），经过的点从空心变实心。
- **右侧之眼**：2D 拼贴放进 3D 空间，靠真透视（近大远小 + 离轴偏移 + 掠过时快速放大出画）产生穿行感。物品依次：法棍照片（倾斜飞入）→ 黄便利贴（回形针 + 逐字打出 + 微透视翻转）→ 蓝登机牌 → 黑明信片 → …… 物品间有红色细绳。
- **时间轴**：菱形刻度是关键帧，可点跳。

## 实现要点

- **真透视**：右窗格外层 `perspective:900px`，场景层 `transform-style:preserve-3d`；每张卡世界坐标 (x,y,z) 固定，相机沿 8 个路径点插值（段内 smoothstep），每帧对场景整体做 `translate3d(-camX,-camY,-camZ)`，透视自然产生近大远小与梯形畸变。卡片临远时按距离加 rotateY/rotateX 小角度，临近摆正 = 「倾斜飞入」。
- **同步是结构性的**：两窗格 + 时间轴都由同一个 `render(t)` 驱动；缓动是 t 的纯函数，所以 scrub 到任意进度与播放到该进度画面逐像素一致。
- **左窗格**是同一套世界坐标的斜投影（SVG）：卡=灰阶平行四边形、路径点=六边形、视锥=线框五点。词汇纪律：页面上只有「命题/证据/支持/反驳/尚缺/来源/可信度/还查不清」。
- **测试参数**：`?demo=progress=0.35`（demo 键的值再当一层 query 解析）把 t 定住，供无头截图。
- **循环**：播完停末帧 + 重播按钮（契约二选一里选这个）。
- **reduced-motion**：无自动播放、直达末帧布局，时间轴可拖，视锥瞬移（段内缓动退化为线性）。

## 可学之处

- 「相机本体可见」让运镜有了叙事主体：观众看的不是幻灯片，是一台机器在工作。左 rig 一根线都不用动，只换右窗格内容就能换一个故事。
- 位移反算比逐卡动画简单得多：卡不动、相机动，一张 3D 证据墙就活了；scrub 精确是白送的。
- 掠过出画不用专门做动画：`z'` 逼近透视距离时自然放大，只在临界带做透明度衰减即可。
- 红绳用 2D 覆盖层按同一投影公式画端点，跟 CSS 3D 卡片严丝合缝。

## 不学之处

- 原片巴黎内容（法棍、登机牌、Three.js Conf 地图）一字不搬。
- 原片位图照片全部换成代码绘制的卡与便利贴，零网络请求。
- 原片 5s 的节奏太快看不清证据，本页放慢到 12s，段间节奏不同（末段放慢给判断卡）。

## 启示

- 叙事类运镜的关键帧不是「画面」而是「站位」：先定 8 个相机站位，内容自然按叙事顺序出现。
- 便利贴打字窗口必须套着卡片在画面里的时段，否则字打给出画后的空气看。
- 同一份世界坐标喂两套渲染（CSS 3D + SVG 斜投影），「编辑视图」和「结果视图」永远不会失同步。
